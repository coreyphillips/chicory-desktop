# Beignet requirements for a managed Floresta backend

Chicory Desktop pins Beignet **0.38.0** (npm gitHead `954d034b13f57b38297406dd0d30dddc1208b192`) and its Electrum transport **rn-electrum-client 0.0.22** (npm gitHead `6c457fece0c35fb75fd0dcad2ca04d9bc6804e54`). The inventory below follows the published packages with the integrity hashes in the desktop runtime lock. Chicory also patches fresh receive address subscription, the wallet's zero-reserve role and encrypted storage. Recheck these contracts when any pin or patch changes. [Runtime lock](../build/runtime/package-lock.json) · [Engine patches](../scripts/apply-engine-patches.mjs) · [Storage patch](../scripts/apply-storage-encryption.mjs)

## Calls to exercise

The transport sends newline-delimited JSON-RPC 2.0 over TCP or TLS. It sends JSON arrays even for some single-item requests. On connect it negotiates `server.version("beignet", "1.4")`, pings and probes a fixed script hash with a single-item balance batch. The exported Beignet peer-discovery utility can also call `server.peers.subscribe`. The desktop wallet starts with its configured endpoint. [Beignet client][client] · [Transport helpers][transport] · [Batch framing][batch]

| Wire method | Behavior needed by the desktop wallet |
| --- | --- |
| `server.version`, `server.ping`, `blockchain.block.header`, `blockchain.headers.subscribe` | Handshake and keepalive. Retrieve block 0 for identity and older headers for reconciliation. Deliver the initial tip and later notifications on the same connection, including reorganizations. Reconnect after a missed block. Chicory's server probe also tries `server.features` for the genesis hash. [Desktop probe](../server/electrum-probe.js) |
| `blockchain.scripthash.get_balance`, `.get_history`, `.listunspent` | Honor batches and per-ID results. Return complete confirmed and mempool history, including heights 0 and -1, and accurate output indices and values in sats. Exercise receive and change addresses across multiple gap windows, UTXOs outside the current window and spent outputs. Beignet reads unconfirmed entries through `get_history`. [Wallet client][client] |
| `blockchain.scripthash.subscribe` | Return a status for each hash, then notify on arrival, confirmation, replacement, eviction and reorg. Compare the first status after reconnect with the status before disconnect. A subscription only identifies a hash. Floresta needs the underlying script to index it. [Subscription implementation][client] |
| `blockchain.transaction.get(txid, true)` | The engine batches verbose requests, even for a single Lightning funding tx. The wallet consumes decoded inputs, outputs and confirmations, including outputs of parent transactions. The Lightning backend extracts `result.hex`. Test both a watched tx and an older parent whose own outputs belong to another wallet. [Wallet formatting][format] · [Lightning backend][backend] |
| `blockchain.transaction.get(txid, false)` | Chicory's receipt, splice payment and drain tracking paths parse raw hex, check the transaction ID and match inputs or destination outputs. Some destination scripts belong to the payee. Include those scripts in desktop watch requirements. [Wallet activity](../server/browser-wallet.js) · [Drain tracking](../server/desktop-drain.js) |
| `blockchain.transaction.get_merkle`, `.broadcast` | Return the real branch and position for a known confirmed transaction. Lightning uses the position to construct and check the short channel ID. Broadcast a disposable signed transaction, compare the returned txid and observe its relay, mempool entry and subsequent confirmation on an independent regtest node. [Lightning backend][backend] · [Channel ID lookup][scid] |
| `blockchain.estimatefee` | The wallet requests 2, 6, 24 and 144 blocks in BTC/kB, converts to sat/vB and rejects unusable values. Test both actual fee data and insufficient data. The regtest wallet uses built-in fees, so a successful regtest payment says nothing about a server's estimates. [Fee selection][fees] |

## Dependencies before enabling local routing

1. **Public watch export and registration.** `GET /wallet/descriptors` returns checksummed public receive/change descriptors with a derivation wildcard. The Lightning watcher separately maintains funding candidates, pre- and post-splice outputs, splice inputs and outputs needed for close, HTLC and breach monitoring. It can recover a script by first fetching an old parent. Beignet needs a supported complete watch snapshot and ordered updates, including ownership, ranges, safe historical bounds and an acknowledgement before an address is exposed or a funding transaction can arrive. Keep watches through disconnects, failed registration and reorgs. The engine's stored wallet birthday is advisory for this Electrum path. [Wallet descriptors][descriptors] · [Birthday semantics][birthday] · [Restored channel watches][restored] · [Funding and output watches][watcher]
2. **Incomplete history must stop decisions.** Lightning's `getTransaction` distinguishes an unavailable lookup from particular missing-transaction messages. Its history reader also skips non-array batch entries, which can yield an empty list on an individual RPC error. When checking gossip, Beignet can refute another channel's announcement if an empty UTXO list arrives at depth 12 or greater. Test a real remote announcement and a dual-funding peer's inputs, even when their scripts are new to the index. A selective index needs a chain-anchored coverage check for every required watch and a way to propagate per-item scan or peer failures. Test partial batches, unknown txids, old parents unavailable from peers and rollback during rescan. Preserve cached wallet data and mark recovery incomplete until fresh reads succeed. [Lightning backend][backend] · [Error classification][client] · [Remote funding and gossip checks][watcher]
3. **Enforce endpoint permission at every caller.** Beignet appends public servers to the candidate list on mainnet, testnet and signet. The transport also has built-in peers when asked to reconnect without a client. Require a strict endpoint policy in these paths, including background reconnects. The default fee policy can fall back to HTTP at mempool.space or Blocktank. `BEIGNET_FEE_SOURCE=electrum` avoids that route but can return a cached fee on failure. Route the manager's server probes, receipt checks and drain checks through the same effective endpoint. Exercise local-only startup, outage and reconnect with external Electrum and HTTP egress observed. Repeat with permission for exactly one external server during catch-up. [Server selection][selection] · [Transport helpers][transport] · [Fee policy][fees] · [Manager routing](../server/wallet-manager.js) · [Desktop Tor routing](../server/desktop-network.js)
4. **Coordinate the switch with the engine.** Chicory's settings path restarts the daemon and the wallet client invalidates pending reads and transaction reviews. The update hold counts HTTP actions. Beignet's `POST /stop` with `drain: true` checks pending payments, direct-funding sends and swap fundings, then stops even if the wait times out. Add an engine handshake that can defer the restart and covers restore, peer-driven channel transitions, payments, splices and closes. Reconcile monitoring, subscriptions and peers before marking the new endpoint active. Verify that a pending or uncertain send is never replayed. [Stop route][stop] · [Drain criteria][drain] · [Host hold](../server/update-hold.js) · [Wallet client](../web/platform/walletClient.ts)
5. **Recover against an empty node directory.** Create funded wallet and channel history using an external server first. Recover using Beignet's supported full-wallet or guardian material, with empty rebuildable chain and transaction caches. Check an old funding tx, a replacement funding candidate, a splice conflict, cooperative and force closes, HTLC claims and breach remedies. Repeat after a week-equivalent absence, data loss and a reorg that changes the funding or close. Preserve guardian fencing and the full backup's channel recency check. Keep channel databases, recovery records and non-reconstructable watch metadata separate from removable node data. [Recovery protocol][recovery] · [Desktop backup](../server/full-backup.js) · [Funded desktop qualification](desktop-qualification.md)
